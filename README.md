# 家計簿

> **公開用リポジトリについて**
> 個人で使っている家計簿アプリ（非公開リポジトリ）から、コードと設計ドキュメントを公開用に書き出したもの。
> 初期データ（大項目・中項目・決済手段・分類ルール）は**一般的な名前のサンプル**に置き換えてあり、
> 実際の家計データ・スプレッドシートの ID・鍵・個人名は含まない。開発履歴（コミット）も含めていない。
>
> - 技術スタック: Next.js 16（App Router）/ React 19 / TypeScript / Tailwind CSS v4 / Recharts / zod / jose、
>   Google Sheets API（サービスアカウント・JWT 署名を自前で実装）、Google Apps Script（LINE ボット側）
> - 設計の要点: DB サーバーを持たずスプレッドシートを DB にする（1 回の batchUpdate で複数タブをまとめて書く・
>   ヘッダー名で列を引くので列の並べ替えに強い・起動時に足りないタブと列を自動で足す）、
>   GAS 時代の運用（請求シート → まとめシート）をそのまま読める読み取り専用画面と突合、
>   LINE ボットと同じ規則で書く割り勘の記録（端数・精算・カード明細との突き合わせ）
> - セキュリティ: インターネットに公開しない前提（127.0.0.1 で起動、Codespaces のポートは Private）。
>   パスワードログイン ＋ 署名付き Cookie、ログイン試行の制限、鍵は Codespaces のシークレットか `.gitignore` 済みの `secrets/` に置く

カード・PayPay・現金の明細を取り込み、**生活費 / 個人支出 / 投資 / 帳尻合わせ** に分類して
月別・年別に集計する、自分専用の家計簿 Web アプリ。

**データは Google スプレッドシートに保存する。**アプリはそのスプレッドシートを読み書きするだけで、
DB サーバーは持たない。アプリはインターネットに公開せず、自分の PC か Codespace の中だけで動かす。

確定した仕様は [`docs/requirements.md`](docs/requirements.md) を参照。
これまで Google Apps Script で回していた「請求シート → 支出シート → まとめシート」の運用を、
そのままアプリに移したもの。GAS との対応は [`docs/requirements.md` §1](docs/requirements.md) にまとめてある。

## できること

- **個人支出と生活費の分割** — 1 件の買い物を「支出 12,000 ＋ 生活費 20,000」のように
  大項目をまたいで分けられる。GAS の `個人支出` 列 / `生活費` 列に相当する
- **使用先（イベント）別の集計** — 「帰省」「家電買い替え」のような使用先をそのまま中項目にし、
  無い中項目は取込時に自動で作る
- **CSV 取込** — Shift_JIS/UTF-8 の自動判定、列マッピングをカード会社ごとにプリセット保存、
  日付・利用先・金額・決済手段による重複スキップ、バッチ単位の取り消し
- **自動分類** — キーワードルールで振り分け、手で直すとその利用先を覚える
- **口座残高** — 起点残高に明細を足し引きした現在残高。チャージ・振替は「銀行口座 → PayPay」の
  ように移動先を選ぶと口座間の残高移動として反映される
- **予実** — 中項目ごとの月の予算（毎月の既定と、特定の月だけの上書き）と、給料・家賃・引き落とし・
  積立のような毎月の予定を登録すると、明細と自動で突き合わせて「済 / まだ / 期日超過」を出し、
  月末の純残高と口座残高の見込みを出す
- **使途ごとの残高** — 個人・生活費・投資・彼女・家族 のような使途ごとに、起点残高 ＋ 収入 − 支出 ± 振替 の残高を出す。
  使途の間でお金を回したときは振替として記録する（口座の残高は変わらない）
- **二人（パートナーとの支出）** — LINE ボット（別リポジトリ（非公開））と同じ「二人の明細」を、自分用に管理・確認する。
  未精算の差額と精算、月ごとの合計・それぞれの負担・費目別・12 か月の推移、明細の絞り込み、精算の履歴、イベント別の集計、
  家計簿との突き合わせ。ここから登録・修正・精算すると、家計簿にも LINE と同じ規則で反映される
- **ダッシュボード** — 今月の収支サマリー、予実（月末見込み・予算超過・これからの予定）、使途ごとの残高と月別推移、
  お金の出入り（内側 = 入ってきたお金、外側 = 使ったお金の二重円グラフ。金額表示）、口座残高、中項目の内訳
- **まとめ表** — 横軸が月・縦軸が大項目 > 中項目のマトリクス。小計・純残高つき、CSV 書き出し可
- **費目とクロス集計** — 内訳ごとに費目（食費・交通費・宿泊費など）を付け、「旅行かつ食費」
  「マラソンかつ交通費」のように中項目 × 費目で集計する。費目は店名からルールで自動でも付く
- **入金の振り分け** — 銀行・現金の入金と電子マネーの受け取りは収入に、カードの返金と
  電子マネーのチャージは支出から差し引く。入金は使用先と同じ名前の個人収入の中項目に入る
- **明細** — 年月・カテゴリ・決済手段での絞り込み、フリーワード検索、インライン編集
- **シート** — GAS 時代の請求シートをそのまま読んで集計する読み取り専用の画面。アプリの数字との突合つき。
  スプレッドシートを直接読むか、コピー&貼り付けで読む（どちらにも書き込まない）
- **項目の一括作成** — まとめシートの項目一覧を貼り付けると、大項目・中項目をまとめて作る
- **払い戻しの差し引き** — 支出側の項目への払い戻し・精算はマイナスで持ち、その項目から差し引く
- **スプレッドシートで直接見る・直す** — 明細・内訳・大項目などがタブごとに並ぶ。
  スプレッドシート側で直した内容も、次にアプリを開いたときに反映される

## 初回セットアップ（GitHub Codespaces）

Codespaces は、ブラウザだけで動く開発環境。PC に Node.js を入れなくてよい。
データは Google スプレッドシートに置くので、Codespace を削除・作り直してもデータは消えない。

### 1. Google 側の準備（10 分ほど）

アプリがスプレッドシートを読み書きするための「サービスアカウント」を作る。
あなたの Google アカウントとは別の、このアプリ専用の身元で、**共有されたファイルにしか触れない。**

1. [Google Cloud コンソール](https://console.cloud.google.com) でプロジェクトを新規作成する
2. 「API とサービス」→「ライブラリ」で **Google Sheets API** を有効にする
3. 「IAM と管理」→「サービス アカウント」→「サービス アカウントを作成」（ロールは付けなくてよい）。
   作ったアカウントを開き、「鍵」タブ →「鍵を追加」→「新しい鍵を作成」→ **JSON** でダウンロードする
4. アプリ用に**新しい** Google スプレッドシートを作り、「共有」で **サービスアカウントのメールアドレス**
   （JSON の `client_email`、`…@….iam.gserviceaccount.com`）を **編集者** として追加する。
   「一般的なアクセス」は **制限付き** のままにする
5. スプレッドシートの URL を控える

> **ダウンロードした JSON は鍵そのもの。**GitHub の Web 画面にアップロードしない、
> チャットやメールに貼らない、リポジトリにコミットしない。

### 2. 鍵を Codespaces のシークレットに入れる

GitHub の「Settings」→「Codespaces」→「Codespaces secrets」→「New secret」で、

- Name: `GOOGLE_SERVICE_ACCOUNT_JSON`
- Value: ダウンロードした JSON の中身をそのまま貼る
- Repository access: このリポジトリだけを選ぶ

GitHub が暗号化して保管し、Codespace の起動時に環境変数として渡す。リポジトリにも
Codespace のディスクにも残らない。**動いている Codespace には反映されないので、
登録したら Codespace を一度停止して起動し直す。**

### 3. Codespace を作る

1. GitHub でこのリポジトリを開く
2. 「Code」→「Codespaces」タブ →「Create codespace on main」
3. 数分待つと、ブラウザ上に VS Code が開く。以降のコマンドは下部の「ターミナル」で打つ

> Codespace の中で、さらに `git clone` しないこと。フォルダが入れ子になり、古いコードが混ざる。

### 4. アプリを用意して起動する

```bash
npm install
npm run setup:env -- --sheet "<スプレッドシートの URL>"   # .env と .env.local を作る。ログインパスワードが表示される
npm run sheets:check                                      # 接続を順に確かめる（止まったら直し方が出る）
npm run db:seed                                           # タブと見出しを作り、初期データを入れる
npm run dev
```

右下に「ポート 3000 で実行中のアプリケーションを使用できます」と出たら「ブラウザーで開く」。
見逃したときは、下部の「ポート」タブ → 3000 の行の地球儀アイコンから開ける。
`setup:env` で表示されたパスワードでログインする。

> ポートの公開範囲は **Private のまま**にする（GitHub にログインした自分しか開けない）。
> Public にすると、URL を知っている人がログイン画面まで来られるようになる。

### 5. 項目をまとめシートから作る（初回だけ）

大項目・中項目を 1 件ずつ作らなくても、まとめシートの項目名をそのまま貼り付けて作れる。

> 初期データ（手順 4 の `db:seed`）は、すでにまとめシートの構成（大項目 14・中項目 64）になっている。
> まとめシートに項目を足したときや、構成を変えたときにこの手順を使う。

1. スプレッドシートの「まとめ」タブで、**項目名の範囲を丸ごと**範囲選択してコピー
   （左に支出、右に収入・投資・生活費 のように 2 列の組が左右に並んでいても、そのまま読める）
2. アプリの「設定」→「カテゴリ」→ 一番下の「まとめの項目を貼り付けて一括作成」を開いて貼り付け、「読み込む」
3. 確認の表で、種別（個人収入 / 個人支出 / 生活費 / 投資 / 帳尻合わせ）が合っているか確かめる。
   作りたくないブロックはゴミ箱アイコンで外せる
4. 「◯ 大項目 / ◯ 中項目を作成」を押す

足すだけで、既存の項目を消したり書き換えたりはしない。項目が増えたら、同じ手順で何度でも継ぎ足せる。
初期データの項目（食費・日用品など）で使わないものは、設定から消してよい。

### 6. 請求シートと繋ぐ（任意）

「シート」画面は、接続しなくても請求シートのコピー&貼り付けで使える。
直接読みたいときは、GAS 時代のスプレッドシートを、手順 1 と**同じサービスアカウント**のアドレスに
**閲覧者** として共有する（アプリ用のスプレッドシートとは別のファイル）。
既定で開くシートを決めておくなら、`.env` と `.env.local` に `BILLING_SHEET_ID="<URL か ID>"` を足す（画面でも変えられる）。
読み取り専用の権限でしか開かないので、アプリから請求シートを書き換えることはできない。

### 次回からの起動

Codespace は使わずにいると 30 分で停止する。再開するときは、GitHub のリポジトリ →「Code」→
「Codespaces」タブの一覧から開き、ターミナルで `npm run dev`。

作り直した Codespace では `npm install` と `npm run setup:env -- --sheet <URL>` を実行し直す
（`.env` は Codespace の中にしか無いため）。

### 自分の PC で動かす場合

Node.js 20 以上があれば動く。鍵はシークレットの代わりに `secrets/google-service-account.json` に置く
（`secrets/` は `.gitignore` 済み。万一リポジトリ直下に置いてしまっても、直下の JSON は既知のもの以外すべて無視される）。

```bash
git clone https://github.com/Enu-pilot/Kakeibo_open.git
cd Kakeibo_open
# 以降は手順 4 と同じ。ブラウザで http://localhost:3000 を開く
```

## 普段の使い方

```bash
npm run dev
```

データはスプレッドシートにあるので、Codespace を作り直してもデータは消えない。
作り直した Codespace では `npm install` と `npm run setup:env` を実行し直す
（`.env` は Codespace の中にしか無いため。スプレッドシートの ID は `--sheet` で渡し直す）。

アプリを新しい版に更新したあとは、一度 `npm run db:seed` を実行する。新しい機能で増えたタブ
（例: 予実機能の `予算`・`予定`、費目の `費目` タブと `費目ID` 列）と見出し、新しい初期データ（費目・
費目ルール・まとめシートの構成の大項目と中項目・請求シートのブロック名の決済手段）のうち無いものだけを足す。
既にある大項目・中項目・明細は消さない（同じ名前の大項目は、種別と並び順だけ標準に戻す）。
足りないタブ・見出しだけなら、`npm run dev` の起動時にも自動で足す（「明細」タブがあるアプリ用のスプレッドシートに限る）。

### 使途の使い方

「そのお金は何のぶんか」（個人・生活費・投資・彼女・家族）ごとに残高を見る。

1. 「設定」→「使途」で、使途ごとに **起点残高と起点日** を入れる（例: 2026/10/1 時点で 個人 120,000・生活費 30,000）。
   起点日より前の明細は数えない
2. 「設定」→「カテゴリ」で、**大項目ごとに使途** を選ぶ（初期データでは 給料・旅行・日常… が個人、パートナーが彼女 など）。
   使途の無い大項目は「未設定」にまとまる。帳尻合わせ（チャージ・口座間の移動）は使途に効かない
3. 使途の間でお金を回したら、「使途」画面で **振替** を記録する（例: 個人 → 投資 30,000）。口座の残高は変わらない
4. ダッシュボードの「使途ごとの残高」で、残高がマイナスの使途には「不足」、その月に残高を減らした使途には「取り崩し」が付く。
   「使途ごとの月別推移」で、使途ごとの入ったお金と出たお金の釣り合いを 12 か月ぶん見られる

### 二人（パートナーとの支出）の使い方

LINE ボット（GAS。別リポジトリ（非公開））が同じスプレッドシートに作る「二人の明細」「二人の精算」「LINE連携」タブを読み書きする。
相手の呼び名は「LINE連携」タブの表示名（LINE のユーザー ID は画面に出さない）。

- **概要**: 未精算の差額（誰が誰にいくら）と件数、「精算する」（対象の明細を外せる・実際に渡した額に直せる）、
  月ごとの合計・それぞれの負担・それぞれが払った額・費目別、**彼女まわりの自分の出費のまとめ**
  （割り勘の自分の負担 ＋ 自分だけ ＋ 精算の記録 ＋ 未確認 ＝ 使途「彼女」の支出。月と全期間。参考に二人の総額・相手の負担）、
  12 か月の推移、明細の登録
- **明細と精算**: 二人の明細を月・精算（未精算 / 精算済み / 過去分の取込）・払った人・費目・イベント・検索で絞り込み、
  未精算の明細を直す・消す。家計簿の明細へのリンク付き。下に精算の履歴（過去分の取込は区別。通常の精算は取り消せる）
- **イベント別**: 中項目（大項目「パートナー」配下の旅行など）ごとに、二人の総額・それぞれの負担・自分だけ・自分の出費。
  二人の明細に中項目が無いときは、結び付けた家計簿の明細の中項目を使う。どちらにも無い明細はメモごとに出し、中項目をまとめて付けられる
- **家計簿との照合**: 口座「彼女精算」の残高と二人の明細から見た残高のずれ、
  LINE で登録した明細と同じ支払いの取込明細（PayPay・銀行の CSV など）の重なり（「取込明細にまとめる」）、
  カード明細の取込待ち（自動で決まらなければ候補から選ぶ）、家計簿に書けなかった明細・消された明細、
  過去分（割り勘アプリなど）の照合（同じ金額を 150 日前〜30 日後から探し、候補が 1 つならまとめて、複数なら選んで結び付ける。家計簿は変えない）
- **二人の時の出費**: 使途「彼女」の大項目の家計簿の明細を「割り勘（二人の明細）」「割り勘（記録なし）」「自分だけ」
  「精算の記録」「未確認」に分けて見る。区分は「明細」タブの「二人の区分」列にだけ入り、LINE のダッシュボード（相手）には出ない

以前の大項目（同じ中項目が並んでいるもの）は、「設定」→「カテゴリ」→「大項目をまとめる」でまとめられる。
まとめ元の中項目はまとめ先の同じ名前の中項目へ（まとめ元の大項目と同じ名前の中項目は、まとめ先の大項目と同じ名前の中項目へ）移り、
明細の内訳・予算・予定・分類ルールも付け替わる。まとめ元はアーカイブされ、金額・集計は変わらない（実行前に何が移るかを確認できる）。

家計簿への書き方は LINE ボットとまったく同じ（自分の負担は大項目「パートナー」の支出、相手の分は「立替 / 彼女立替」（帳尻合わせ）と
口座「彼女精算」）。自分の支出・予算・使途に数えるのは自分の負担だけになる。
アプリから登録・修正・精算しても、相手への LINE 通知は送らない（相手は LINE のダッシュボードで見られる）。
書き込み先（「立替 / 彼女立替」「彼女精算」）は LINE ボットの GAS の `setup` が作る。無いときは明細だけを登録し、
「家計簿との照合」に出る（作ってから「今すぐ照合」で書き直せる）。

### 予実の使い方

画面上部の「予実」を開く。

1. **予定を追加** — 「給料 / 毎月 25 日 / 300,000 円 / 入金先: 銀行口座」のように、毎月決まって
   動くお金を登録する。同じ中項目・同じ月の明細のうち金額がいちばん近いものを実績とみなし、
   「済」になる。予定日を過ぎても明細が無ければ「期日超過」になる（取込漏れ・分類違いの目印）。
   日を 31 にすると月末。開始月・終了月でボーナス月や積立の期間も表せる
2. **予算を追加** — 食費・日用品など中項目ごとに月の予算を決める。「毎月」か「その月だけ」を選べる
3. 上のまとめに、収入・出ていくお金・純残高の **実績 / 予 / 月末見込み** が出る。
   口座を指定した予定は、口座残高の見込みにも反映される

見込みは楽観的にならないように、支出系は「実績 ＋ まだ来ていない予定 ＋ 予算の残り（使い切る前提）」、
収入は「実績 ＋ まだ来ていない予定」で出す（収入の予算は目標であって確約ではないため）。

### 日々の使い方

| やりたいこと | 画面 |
|---|---|
| カード会社の CSV を取り込む | 「取込」。使用先の列を指定すると中項目に、無い中項目は自動で作られる。入金の扱いと費目も行ごとに直せる |
| 1 件ずつ手で入れる・直す | 「明細」。払い戻しはマイナスで入力する。内訳ごとに費目を選べる |
| 予算・給料日などの予定と比べる | 「予実」 |
| 月ごとの大項目 > 中項目の表を見る | 「まとめ」。CSV に書き出せる |
| 旅行かつ食費、のように掛け合わせで見る | 「まとめ」の下のクロス集計（中項目 × 費目）。数字を押すと該当の明細へ |
| 請求シートの内容を集計・グラフで見る | 「シート」で読み込む（直接読む or 貼り付け） |
| 請求シートの過去の明細をアプリに入れる | 「シート」で読み込み、下の「アプリに取り込む」（下の「請求シートの取り込み」） |
| 請求シートとアプリの数字が合っているか見る | 「シート」で読み込むと、下に突合（月別・中項目別の差分）が出る |
| 使途ごとの残高を見る・使途の間でお金を回す | 「使途」。起点残高は「設定」→「使途」、大項目ごとの使途は「設定」→「カテゴリ」 |
| 項目・費目・分類ルール・決済手段を変える | 「設定」。中項目の並べ替え・別の大項目への移動もここで |

金額の符号: 支出側の項目では、払い戻し・精算はマイナスとしてその項目から差し引く。
収入（給料）は振込がプラス。まとめシートと同じ数え方になる。

入金の扱い（取込・シート画面・請求シートの取り込みで同じ規則）:

| 決済手段の種類 | 入金の扱い |
|---|---|
| 銀行・現金 | 収入。使用先と同じ名前の個人収入の中項目へ（無ければ帳尻合わせ・投資の同名、使用先が大項目名ならその大項目の同名、それも無ければ「収入内訳」の下に同じ名前で作る） |
| 電子マネー | 人からの受け取り（内容に「受取」「受け取」「送金を受」）は収入、チャージやポイントは差し引き |
| クレジットカード | 返品・取消として、その中項目から差し引き（マイナスの内訳） |

取込のプレビューでは、入金の行の「入金 → 収入 / 入金 → 差し引き」を押すと行ごとに切り替えられる。
決済手段の種類は「設定」→「決済手段」で確認・変更できる（請求シートのブロック名と同じ名前の決済手段があれば、その種類を使う）。

費目（食費・交通費・宿泊費…）は、大項目 > 中項目とは別の軸で、明細の内訳ごとに 1 つ付けられる。
「設定」→「費目」で追加・並べ替え（クロス集計の列の順）ができる。自動分類ルールで店名から付けられ
（初期ルール: セブン → 食費、ＪＲ → 交通費 など）、取込の CSV や請求シートに「費目」列があればその値を使う。

> 取込で「使用先」列を使うとき、「未マッチ行の既定カテゴリ」は空のままにしておく。
> 使用先の無い行（カードの引き落としなど）を取り込むと、カードの利用額と二重に数えてしまう。
> シート画面も同じ理由で、使用先の無い行は集計しない。

### 請求シートの取り込み

GAS 時代の請求シートにある過去の明細を、アプリのデータにまとめて入れられる。

1. 「シート」画面で請求シート（例: `請求2026`）を読み込む。集計と、アプリとの突合を確かめる
2. 下の「アプリに取り込む」で、取り込む件数・新しく作る中項目と決済手段・月ごとの件数を確かめる。
   期間で区切ることもできる
3. 「◯ 件を取り込む」を押す

- 読み方は「シート」画面の集計と同じ。ブロック名（メインカード・PayPay など）が決済手段、使用先が中項目になる。
  支出側の払い戻しはマイナスで入る
- **使用先の無い行（カードの引き落としなど）は取り込まない。**カードの利用額と二重に数えないため（GAS のまとめと同じ）
- 使用先と同じ名前の中項目が無いときは、その名前で中項目を作る（作る先の大項目を選べる）。作らない設定にすると、
  自動分類ルール → 「未分類」の順で決める。先に「設定」→「まとめの項目を貼り付けて一括作成」で項目を揃えておくと、作られる中項目が少なくて済む
- **何度取り込んでも増えない。**同じ日・同じ利用先・同じ金額・同じ決済手段の明細は取り込み済みとして飛ばす。
  シートの中で同じ内容の行が 2 つある（同じ日に同じ運賃を 2 回払った等）ときは、2 件とも入る
- 取り込みは 1 件の取込履歴として残るので、「取込」画面の「最近の取り込み」からまとめて取り消せる
- 取り込んだ決済手段の口座残高を合わせるには、「設定」→「決済手段」で起点残高と起点日を入れる

## スプレッドシートの読み込みと API の料金

**データの正はスプレッドシート。**アプリはそれを読んで表示し、アプリからの追加・変更もスプレッドシートに書き込む。

- **起動した時点で全データを読み込んでいる。**`npm run dev` / `npm run start` の起動時に全タブを読み、
  ターミナルに `✓ スプレッドシートを読み込みました（明細 ◯ 件 …）` と出る。最初の画面から待たずに表示できる
- 読んでから 30 秒以内は、手元の写しをそのまま使う（Google には問い合わせない）
- 30 秒を過ぎると、手元の写しで即座に表示しつつ、裏で読み直す。次の表示から新しい内容になる
- アプリから保存したときは、書き込む直前と直後に必ず読み直すので、保存した内容はすぐ画面に出る
- スプレッドシートを直接直した内容をすぐ見たいときは、画面右上の「◯◯:◯◯ に読み込み」を押す

**API の料金:** Google Sheets API の通常の利用は無料。回数制限は、読み取り・書き込みそれぞれ
1 分あたり 300 回（プロジェクト全体）・60 回（ユーザーごと）。上の仕組みで、画面を何度開いても
読み取りは 30 秒に多くて 1 回、保存 1 回につき読み取り 2 回・書き込み 1 回に収まるので、1 人で使う分には制限に届かない。
制限に当たったときは、アプリが少し待って自動でやり直す。

なお Google は「制限を超えたリクエストは、2026 年中に Google Cloud の請求先アカウントへの課金対象にする予定」としている。
**このアプリ用の Google Cloud プロジェクトには、請求先アカウント（クレジットカード）を紐づけないこと。**
紐づけていなければ、制限を超えても課金されず、一時的に断られるだけになる
（[Google Sheets API の Usage limits](https://developers.google.com/workspace/sheets/api/limits)）。

## 公開しない運用での守り

アプリはインターネットに出さない前提で作っている。そのうえで次を済ませてある。

| 対策 | 内容 |
|---|---|
| 待ち受け | `npm run dev` / `npm run start` は `127.0.0.1` だけで待ち受ける。同じ Wi-Fi の他の端末からは開けない |
| Codespace のポート | 既定の「Private」のままなら、GitHub にあなたとしてログインしたブラウザしか開けない |
| ログイン | パスワードは 8 文字以上・雛形の値は拒否。5 回失敗すると締め出し（最大 15 分、失敗のたびに倍） |
| セッション | 署名鍵（`AUTH_SECRET`）は 32 文字以上でなければ起動を拒否 |
| スプレッドシート | あなたとサービスアカウントしか開けない（「制限付き」のままにしておくこと） |
| 鍵が漏れた場合の範囲 | サービスアカウントは共有されたファイルにしか触れない。Drive の他のファイルやメールには届かない |
| 鍵の失効 | Google Cloud でその鍵を削除すれば即座に無効になる。新しい鍵を作ってシークレットを入れ替える |
| 秘密情報 | `.env*`・`secrets/`・`backups/`・直下の JSON は `.gitignore` 済み。`.env` は所有者だけが読める権限で作る |
| 入力 | 全 API ルートで zod による検証。利用先に `=IMPORTXML(...)` のような文字列が来ても、式ではなく文字列として保存する |

**自分でやっておくこと:** PC のディスク暗号化（macOS は FileVault、Windows は BitLocker）と、
Google アカウントの 2 段階認証。この 2 つはアプリ側では代わりが効かない。

## スプレッドシートを直接直すとき

- **列の並べ替えや、自分用の列の追加は自由。**アプリは見出しの名前で列を探し、知らない列には触らない
- **見出し（1 行目）の文字は変えない。**変えるとその列がアプリから見えなくなる。
  消してしまったら `npm run db:seed` で補える
- **`ID` 列は変えない。**明細と内訳、中項目と大項目は ID でつながっている
- 日付は `2026-08-03` でも `2026/8/3` でも、金額は `1234` でも `¥1,234` でも読める
- `予算`・`予定` タブの月は `2026-09` でも `2026/9` でも `2026年9月` でも読める。
  `予算` の `月` を空にすると毎月の既定、月を入れるとその月だけの上書きになる
- 直した内容は、30 秒以内にアプリへ反映される（下の「スプレッドシートの読み込みと API の料金」）。
  すぐに反映したいときは、画面右上の「◯◯:◯◯ に読み込み」ボタンを押すと読み直す
- 行を消して食い違いが出ていないかは `npm run sheets:check` で確かめられる
  （例: 中項目の行を消したのに、その中項目を使う内訳が残っている）
- **アプリで保存している最中に、同じタブの行を挿入・削除しない。**
  アプリは読み込んだ時点の行番号で書き込むため、ずれると別の行を書き換えるおそれがある

## うまくいかないとき

まず `npm run sheets:check` を実行する。どの段階で止まっているかと、直し方が出る。

| 出てくるメッセージ | 直し方 |
|---|---|
| 権限がありません | スプレッドシートの「共有」に、表示されたサービスアカウントのアドレスを「編集者」で追加する |
| Google Sheets API が有効になっていません | Google Cloud で Sheets API を有効にする（反映に数分かかることがある） |
| スプレッドシートが見つかりません | `npm run setup:env -- --sheet <URL>` で設定し直す |
| シークレット GOOGLE_SERVICE_ACCOUNT_JSON が見つかりません / 鍵ファイルが見つかりません | シークレットを登録したあと Codespace を停止して起動し直したか、登録先が「Actions」ではなく「Codespaces」のシークレットか、名前と対象リポジトリが合っているかを確認。ターミナルで `[ -n "$GOOGLE_SERVICE_ACCOUNT_JSON" ] && echo あり \|\| echo なし` を実行すると届いているか分かる |
| 「明細」タブがありません / 列がありません | `npm run db:seed` |
| Google の認証に失敗しました | 鍵が削除されていないか確認。削除していたら新しい鍵を作り直す |
| `Can't reach database server at 127.0.0.1:5432` / `P1001` / `Missing script: "setup:env"` | PostgreSQL 版（古い版）のコードが動いている。下の「PostgreSQL 版から切り替える」の手順で切り替える |
| 画面は出るがボタンが反応しない | ブラウザで開いている URL が `https://…app.github.dev` か確認（`next.config.ts` でこのドメインだけ許可している） |
| 3000 番ポートが既に使われている | 前の `npm run dev` が残っている。そのターミナルで Ctrl+C するか、ターミナルを閉じる |

アプリの画面にも同じメッセージが出る。

### PostgreSQL 版から切り替える（前から使っている Codespace の場合）

このアプリは以前 PostgreSQL にデータを置いていた。そのころに作った Codespace では、古いコードのまま
動いていることがある。次のどれかが出たら、この手順で切り替える。

- `Can't reach database server at 127.0.0.1:5432`
- `Error: P1001`
- `npm error Missing script: "setup:env"`
- 起動時に `The "middleware" file convention is deprecated` と出る

**1. 動いているアプリを止め、今の状態を確かめる**

`npm run dev` を動かしているターミナルで Ctrl+C を押してから、1 行ずつ実行する。

```bash
cd /workspaces/Kakeibo_open
git status
```

`git status` に `.env` や `.env.local` が「modified」と出たら、先に元に戻す。
どちらも PostgreSQL 版の古い設定で、手順 4 で作り直すので消えてよい。

```bash
git restore .env .env.local
```

**2. 最新のコードにする**

GitHub でプルリクエストをマージしても、Codespace の中のファイルは変わらない。必ず `git pull` で取ってくる。

```bash
git fetch origin
git switch main
git pull origin main
```

確かめ方: `npm run` の一覧に `setup:env` と `sheets:check` があり、`db:deploy` が無ければ新しい版になっている。
まだ `db:deploy` があるなら古いままなので、ここで止めて `git pull` の出力を確かめる。

**3. 古い版が残したものを消す**

古い版は、データベースに接続するためのコードを `src/generated/` に自動で作っていた。
Git の管理外なので `git pull` では消えず、残っているとビルドや型チェックで引っかかる。
前回の画面の作りかけ（`.next/`）も一緒に消す。どちらも、必要なものは次の手順で作り直される。

```bash
rm -rf src/generated .next
```

Codespace の中でさらに `git clone` していないかも確かめる。

```bash
ls /workspaces/Kakeibo_open/Kakeibo_open
```

ファイルの一覧が出たら、それが入れ子になった古いコピー。残すと古いコードが混ざるので消す
（「No such file or directory」と出れば何もしなくてよい）。

```bash
rm -rf /workspaces/Kakeibo_open/Kakeibo_open
```

**4. 入れ直して、スプレッドシートに繋ぐ**

```bash
npm install
npm run setup:env -- --sheet "<アプリ用スプレッドシートの URL>"
npm run sheets:check
npm run db:seed
npm run dev
```

- `setup:env` は PostgreSQL 用の設定（`DATABASE_URL` など）を `.env` から取り除き、新しいログインパスワードを表示する
- `sheets:check` が「接続できています」で終わらなければ、表示された直し方に従う。鍵のシークレットを
  登録したばかりなら、Codespace を一度停止して起動し直してから実行する
- 使わなくなった PostgreSQL のコンテナが残っていても害は無い。気になるなら `docker ps -a` で確かめて `docker rm -f <名前>` で消す
- PostgreSQL 版に入れていたデータは移らない。必要ならカードの CSV を取り込み直す

> コマンドは 1 行ずつ貼り付けて実行する。`# ...` のコメントごと何行もまとめて貼ると、
> 端末の折り返しでコメントの途中が次の行になり、コマンドとして実行されてしまうことがある。
